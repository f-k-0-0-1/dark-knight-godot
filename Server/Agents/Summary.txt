1. SYSTEM ARCHITECTURE OVERVIEW
-------------------------------------------------------------------
The networking pipeline runs as a native GDScript implementation, replacing compiled C socket binaries. This eliminates external compilation dependencies and platform execution warnings.
- SERVER (TCPServer): A native background listener that binds to the local port, accepts incoming TCP connections, upgrades them to WebSocket connections, and processes incoming data frames natively.
- CLIENT (WebSocketPeer): A native persistent WebSocket client that establishes a continuous, secure connection to the host address. Sockets are kept alive to ensure instantaneous delivery without handshake latency.
- PARADIGM (Local Authority): Enemy AI and physics are calculated locally for each client to prevent network lag and visual desync. State changes (deaths, item pickups) are broadcast via discrete packets to maintain logical consistency across peers.

2. MULTIPLAYER GAMEPLAY SYNCHRONIZATION & STABILITY OVERHAUL
-------------------------------------------------------------------
A. Scene Transition & Network State Stability
- Implemented remote player reparenting via `_on_scene_node_added` in `sync_node.gd`. Remote avatars are now automatically moved to the new scene root during level transitions, preventing them from being freed and causing null-reference crashes.
- Added idempotent socket state checking to `_start_host()` to prevent `ERR_ALREADY_IN_USE` C++ engine crashes when redundant host commands are issued.
- Modified `player.gd` to ensure remote players safely despawn on death without triggering `SceneManager.change_scene("retry_menu")`, which previously caused abrupt scene teardowns for the host.

B. Enemy AI & Targeting Standardization
- Enforced strict local-player targeting (`is_local == true`) across all enemy scripts (`slime.gd`, `flying_demon.gd`, `spider.gd`, `shardsoul.gd`). Enemies no longer chase interpolated remote avatars, resolving the "invisible enemy" desync.
- Standardized the `take_damage(amount: int, source_position: Vector2)` method signature across all enemies to prevent silent method rejection when hit by projectiles or melee attacks.
- Implemented null-safe runtime camera resolution in enemy scripts. Screen shake effects now dynamically fallback to the colliding body's camera node if the cached reference is invalid, preventing `_on_hitbox_body_entered` crashes.
- Added `enemy_sync` network packets. When an enemy dies locally, its unique scene-path ID is broadcasted to delete the corresponding entity on the remote client's screen.

C. Entity & Progression Synchronization
- Implemented `coin_sync` and `pickup_sync` packets in `coin.gd` and `collectable_lives.gd`. Collectibles generate a unique ID on spawn; when collected, the ID is broadcasted so the remote client can delete its local instance, preventing resource duplication.
- Implemented `level_sync` packets in `flag.gd`. When the local player completes a level, the next scene name is calculated and broadcasted, forcing remote clients to automatically transition to the correct subsequent level.

D. Performance Optimization
- Refactored Cloudflare initialization to a lazy-load execution model. The `_check_cloudflare_installed()` file-system scan is bypassed on game startup and only executes when the user explicitly initiates a tunnel (`chat -s`), resolving startup performance bleeding.
- Removed preemptive boolean checks in `cheat_command.gd` that were blocking the lazy-load Cloudflare verification process.

5. UNIFIED PLAYER ENTITY ARCHITECTURE
-------------------------------------------------------------------
